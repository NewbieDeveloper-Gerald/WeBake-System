Table 1. Admins
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the administrator account
email VARCHAR(255) Yes Unique Administrator’s email address used for system login
password_hash VARCHAR(255) Yes — Securely hashed administrator password
reset_token_hash VARCHAR(255) No — Hashed password-reset token
reset_expires_at DATETIME No — Expiration date and time of the reset token
created_at DATETIME Yes — Date and time the account was created
updated_at DATETIME Yes — Date and time the account was last updated
Table 2. Members
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the customer member account
full_name VARCHAR(255) Yes — Full name of the customer
email VARCHAR(255) Yes Unique Customer’s email address used for authentication
email_verified_at DATETIME No — Date and time when the customer verified their email via OTP
contact VARCHAR(50) Yes — Customer’s mobile or telephone contact number
address TEXT Yes — Default delivery address of the customer
password_hash VARCHAR(255) Yes — Securely hashed customer password for account login
created_at DATETIME Yes — Date and time the customer registered their account
updated_at DATETIME Yes — Date and time the account profile was last updated
Table 3. Carts
Field Data Type Required Key Description
member_id BIGINT Yes Primary Key, Foreign Key References members(id) representing the member owning the cart
updated_at DATETIME Yes — Date and time the shopping cart was last modified
Table 4. Cart_Items
Field Data Type Required Key Description
member_id BIGINT Yes Composite Primary Key, Foreign Key References carts(member_id) identifying the active cart
product_id BIGINT Yes Composite Primary Key, Foreign Key References products(id) identifying the selected bread item
bundles INT Yes — Number of wholesale bundles added to the cart
Table 5. Products
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the bakery product
name VARCHAR(255) Yes Unique Official product name (e.g., Mamon, Otap, Butter Toast)
description TEXT Yes — Detailed description, texture, and product characteristics
price_bundle_centavos INT Yes — Wholesale price per bundle in centavos (e.g., 10500 = ₱105.00)
pieces_per_bundle INT Yes — Number of individual bread pieces contained in one bundle
piece_price_centavos INT Yes — Retail price per individual piece in centavos (e.g., 500 = ₱5.00)
stock_pieces INT Yes — Current stock available counted in individual pieces
low_stock_threshold_pieces INT Yes — Minimum piece threshold triggering a low-stock alert
image_url TEXT Yes — Relative path or URL to the official product packaging photo
is_archived BOOLEAN Yes — Flag indicating if product is hidden from public storefront
created_at DATETIME Yes — Date and time the product record was added to catalog
updated_at DATETIME Yes — Date and time the product information was last updated
Table 6. Orders
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the wholesale order
order_code VARCHAR(50) Yes Unique Tracking reference code of the order (e.g., WB-XXXX)
member_id BIGINT No Foreign Key References members(id); null for guest checkouts
customer_name VARCHAR(255) Yes — Customer full name entered during checkout
customer_email VARCHAR(255) Yes — Customer email address for order notifications
customer_contact VARCHAR(50) Yes — Contact phone number for delivery dispatch
delivery_address TEXT Yes — Complete destination address for bread delivery
subtotal_centavos INT Yes — Total price of all ordered line items in integer centavos
total_centavos INT Yes — Final total payable order amount in integer centavos
downpayment_centavos INT Yes — Required 50% deposit amount in integer centavos
downpayment_paid_centavos INT Yes — Verified downpayment amount received in integer centavos
balance_due_centavos INT Yes — Remaining unpaid balance amount in integer centavos
payment_method VARCHAR(20) Yes — Payment method selected (GCASH or MAYA)
status VARCHAR(50) Yes — Current lifecycle state of the order
rejection_reason TEXT Yes — Stated explanation if payment verification was rejected
resubmit_count INT Yes — Number of times customer resubmitted proof of payment
idempotency_key VARCHAR(255) No Unique Cryptographic token preventing duplicate checkout orders
created_at DATETIME Yes — Date and time the order was initially placed
updated_at DATETIME Yes — Date and time the order was last updated
Table 7. Order_Items
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the order line item
order_id BIGINT Yes Foreign Key References orders(id) indicating parent order
product_id BIGINT No Foreign Key References products(id) indicating purchased product
product_name VARCHAR(255) Yes — Historical snapshot of product name at purchase time
pieces_per_bundle INT Yes — Historical snapshot of packaging size at purchase time
bundles INT Yes — Number of wholesale bundles ordered
unit_price_centavos INT Yes — Historical snapshot of bundle price in centavos
line_total_centavos INT Yes — Total calculated price for this line item in centavos
Table 8. Payments
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the payment transaction
order_id BIGINT Yes Foreign Key References orders(id) linking payment to order
stage VARCHAR(20) Yes — Payment phase (DOWNPAYMENT or BALANCE)
channel VARCHAR(20) Yes — Remittance platform (GCASH, MAYA, or CASH)
amount_centavos INT Yes — Remitted monetary amount in integer centavos
reference_number VARCHAR(100) Yes — Financial transaction reference number from receipt
proof_storage_path TEXT Yes — Secure storage path to the uploaded receipt screenshot
verification_status VARCHAR(20) Yes — Verification status (PENDING, VERIFIED, or REJECTED)
verified_at DATETIME No — Date and time the receipt was verified by administrator
created_at DATETIME Yes — Date and time the payment proof was uploaded
Table 9. Refund_Requests
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the refund request
order_id BIGINT Yes Unique, Foreign Key References orders(id) enforcing 1-to-1 refund relation
reason TEXT Yes — Reason explanation for requesting the refund
reason_source VARCHAR(20) Yes — Origin of request (CUSTOMER or ADMIN_REJECTION)
wallet_type VARCHAR(20) No — Recipient e-wallet provider (GCASH or PAYMAYA)
account_number VARCHAR(50) Yes — Recipient mobile account number receiving refund
account_name VARCHAR(255) Yes — Account holder name on the recipient e-wallet
refund_amount_centavos INT Yes — Amount to be returned to customer in integer centavos
status VARCHAR(30) Yes — Lifecycle status of the refund request
requested_at DATETIME Yes — Date and time the refund was submitted
processed_at DATETIME No — Date and time the refund payout was finalized
admin_reference_number VARCHAR(100) Yes — Transaction reference number for the completed payout
admin_note TEXT Yes — Internal remarks recorded by the administrator
Table 10. Order_Status_History
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the status audit record
order_id BIGINT Yes Foreign Key References orders(id) tracking progression
old_status VARCHAR(50) No — Previous status state prior to change
new_status VARCHAR(50) Yes — Updated new status state
changed_by VARCHAR(20) Yes — Actor who initiated change (CUSTOMER, ADMIN, or SYSTEM)
changed_at DATETIME Yes — Date and time the status transition occurred
note TEXT Yes — Additional context or remarks regarding the transition
Table 11. Stock_Movements
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the product stock movement
product_id BIGINT Yes Foreign Key References products(id) indicating affected bread item
change_pieces INT Yes — Signed quantity in pieces (negative for sales, positive for restocks)
reason VARCHAR(50) Yes — Movement cause (APPROVAL_DEDUCTION, POS_SALE, RESTOCK, etc.)
order_id BIGINT No Foreign Key References orders(id) if triggered by an online order
note TEXT Yes — Audit trail note or reference memo
created_by VARCHAR(100) Yes — Staff username or process executing the stock change
created_at DATETIME Yes — Exact date and time the movement was logged
Table 12. Walkin_Sales
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the counter walk-in sale
sale_code VARCHAR(50) Yes Unique Tracking reference number of POS receipt (e.g. POS-XXXX)
total_centavos INT Yes — Total sale charge in integer centavos
cash_received_centavos INT Yes — Cash handed by walk-in customer in integer centavos
change_centavos INT Yes — Change amount returned to customer in integer centavos
created_by VARCHAR(100) Yes — Cashier username or staff who processed transaction
created_at DATETIME Yes — Date and time the transaction occurred
Table 13. Walkin_Sale_Items
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the walk-in sale item
sale_id BIGINT Yes Foreign Key References walkin_sales(id) indicating parent sale
product_id BIGINT No Foreign Key References products(id) indicating product sold
product_name VARCHAR(255) Yes — Historical snapshot of product name at transaction time
pieces_per_bundle INT Yes — Packaging ratio snapshot at transaction time
unit VARCHAR(10) Yes — Unit sold (BUNDLE or PIECE)
qty INT Yes — Quantity of units purchased
unit_price_centavos INT Yes — Price per unit charged in integer centavos
line_total_centavos INT Yes — Total price for this line item in integer centavos
Table 14. Ingredients
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the raw bakery ingredient
name VARCHAR(255) Yes Unique Official ingredient name (e.g. All-Purpose Flour, White Sugar)
stock_quantity DECIMAL(12,3) Yes — Current inventory volume on hand
unit VARCHAR(20) Yes — Unit of measurement (e.g., kg, pcs, sacks)
reorder_level DECIMAL(12,3) Yes — Minimum stock threshold triggering a restock alert
cost_per_unit DECIMAL(12,2) No — Estimated purchase cost per unit in Philippine Pesos
expiry_date DATE No — Expiration date of the current ingredient batch
stock_updated_at DATETIME No — Date and time stock level was last updated
created_at DATETIME Yes — Date and time ingredient was added to inventory
updated_at DATETIME Yes — Date and time ingredient details were last modified
Table 15. Inventory_Movements
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the ingredient movement record
ingredient_id BIGINT Yes Foreign Key References ingredients(id) indicating ingredient adjusted
movement_type VARCHAR(20) Yes — Movement category (restock, usage, adjustment, waste)
quantity_change DECIMAL(12,3) Yes — Signed volume change amount added or deducted
quantity_before DECIMAL(12,3) Yes — Stock volume immediately before transaction
quantity_after DECIMAL(12,3) Yes — Resulting stock volume immediately after transaction
unit_cost DECIMAL(12,2) No — Purchase unit cost associated with this stock entry
reason TEXT No — Audit explanation, delivery receipt, or baking batch memo
created_by VARCHAR(100) Yes — Staff username or baker who performed the adjustment
created_at DATETIME Yes — Date and time the inventory movement was logged
Table 16. Reviews
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the customer review
order_id BIGINT No Foreign Key References orders(id) linking feedback to an order
product_id BIGINT No Foreign Key References products(id) indicating reviewed item
member_id BIGINT No Foreign Key References members(id) identifying reviewer account
display_name VARCHAR(255) Yes — Display screen name shown on public testimonial
rating SMALLINT Yes — Customer rating score ranging from 1 to 5 stars
text_en TEXT Yes — Written review commentary and feedback text
is_seed BOOLEAN Yes — Flag identifying initial template reviews from live orders
created_at DATETIME Yes — Date and time the review was submitted
Table 17. Otp_Codes
Field Data Type Required Key Description
id BIGINT Yes Primary Key Unique identifier for the verification code record
email VARCHAR(255) Yes — Recipient email address the OTP was sent to
code_hash VARCHAR(255) Yes — Secure cryptographic hash of the 6-digit one-time code
purpose VARCHAR(20) Yes — Action scenario (REGISTER, CHECKOUT, or RESET)
expires_at DATETIME Yes — Expiration date and time of the OTP (typically 5–10 min)
attempts INT Yes — Count of failed verification attempts to block brute-force
verified_at DATETIME No — Date and time the code was successfully validated
consumed_at DATETIME No — Date and time the validated code was consumed by the action
created_at DATETIME Yes — Date and time the verification code was generated
Table 18. Settings
Field Data Type Required Key Description
key VARCHAR(100) Yes Primary Key Unique configuration key identifier (e.g., gcash_qr)
value TEXT Yes — Stored configuration setting value or QR image URI
updated_at DATETIME Yes — Date and time the configuration setting was last updated
